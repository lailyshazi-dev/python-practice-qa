# День 72: mock network через `page.route`

## Цель урока

Перехватить browser-запрос и вернуть заранее подготовленный ответ, чтобы тестировать frontend независимо от реального backend.

## Что сделано

- Создан `tests/ui/test_network_mock.py`.
- Добавлен UI-тест с `page.route()`.
- Запрос `**/api/status` перехватывается до отправки на сервер.
- `route.fulfill()` возвращает mock JSON.
- Тест выполняет browser `fetch` и проверяет полученные данные.

## Перехват запроса

```python
def fulfill_status(route: Route):
    route.fulfill(
        status=200,
        content_type="application/json",
        body='{"status": "ok", "source": "mock"}',
    )

page.route(
    "**/api/status",
    fulfill_status,
)
```

`page.route()` регистрирует обработчик для подходящего URL. Когда браузер вызывает такой URL, Playwright передаёт управление callback вместо реального сервера.

`route.fulfill()` завершает запрос искусственным ответом: status, headers или content type и body.

## Что проверяет тест

```python
result = page.evaluate(
    """
    async () => {
        const response = await fetch("/api/status");

        return {
            status: response.status,
            body: await response.json(),
        };
    }
    """
)
```

Тест выполняет запрос из контекста браузера. Он получает mock-ответ и проверяет, что frontend мог бы обработать status и JSON.

Важно: `page.evaluate()` здесь используется только для учебного вызова browser API. В настоящем приложении запрос обычно запускается кликом пользователя или кодом frontend.

## Mock и реальный backend

Mock позволяет изолировать frontend от backend. Это полезно, когда backend ещё не готов, внешний сервис нестабилен или нужно воспроизвести редкую ошибку.

Mock не доказывает, что настоящий API работает. Поэтому в проекте должны существовать и UI-тесты с mock, и отдельные интеграционные/API-тесты с реальным тестовым backend.

## Реальные примеры

### Успешный ответ

Frontend получает:

```json
{"status": "ok"}
```

Тест проверяет успешное отображение данных.

### Ошибка сервера

Можно вернуть:

```python
route.fulfill(
    status=500,
    content_type="application/json",
    body='{"error": "Internal Server Error"}',
)
```

Так проверяют сообщение об ошибке, кнопку повторной попытки и отсутствие повреждённого UI.

### Пустой список

Можно вернуть `{"items": []}` и проверить empty state: «Данные не найдены».

### Медленный ответ

Через `route` можно задержать ответ и проверить spinner или timeout. Такие сценарии важны для медленных сетей и мобильных пользователей.

## Mock versus stub

В бытовой практике термины часто используют как синонимы. Mock обычно означает управляемую замену зависимости, которая может проверяться или возвращать заданные данные. Stub чаще означает простой источник заранее подготовленного ответа.

В нашем тесте `route.fulfill()` — управляемая подмена network-ответа.

## Важные правила

- Регистрируй route до действия, которое вызывает запрос.
- Используй точный URL или понятный glob.
- Не оставляй mock включённым для тестов, которым нужен реальный backend.
- Проверяй не только status, но и body или видимый UI-результат.
- Не подменяй все зависимости без необходимости: иначе тест перестанет проверять интеграцию.
