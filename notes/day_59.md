## Что я понял

Переменная окружения хранится вне исходного кода и доступна процессу во время запуска программы. Это позволяет использовать разные настройки без изменения кода:

```python
import os


def get_api_token() -> str | None:
    return os.getenv("API_TOKEN")
```

`os.getenv("API_TOKEN")` возвращает строку со значением переменной. Если переменная не задана, функция возвращает `None`.

Настоящие токены, пароли и ключи нельзя записывать в код, тесты, commit или публичный репозиторий. В тесте используется только фиктивное значение `test-token`.

## Где это нужно в реальной работе

- Локальный запуск: разработчик задаёт свой token в окружении компьютера.
- CI/CD: GitHub Actions, GitLab CI или Jenkins получает token из защищённого хранилища secrets.
- Разные стенды: один и тот же код запускается с отдельными настройками для `dev`, `stage` и `prod`.
- Защищённые API: автотесты получают учётные данные во время запуска, не сохраняя их в Git.
- Docker и облачные сервисы: настройки передаются контейнеру или приложению при запуске.

Пример локального запуска в PowerShell:

```powershell
$env:API_TOKEN = "real-token-from-secure-storage"
.\.venv\Scripts\python.exe -m pytest
```

После закрытия терминала или удаления переменной код останется тем же, изменится только окружение запуска.

## Как `monkeypatch` изолирует тесты

```python
def test_get_api_token_returns_environment_value(monkeypatch):
    monkeypatch.setenv("API_TOKEN", "test-token")

    assert get_api_token() == "test-token"
```

`monkeypatch.setenv()` временно создаёт или заменяет переменную. После завершения теста pytest автоматически восстанавливает окружение.

```python
def test_get_api_token_returns_none_when_missing(monkeypatch):
    monkeypatch.delenv("API_TOKEN", raising=False)

    assert get_api_token() is None
```

`monkeypatch.delenv(..., raising=False)` временно удаляет переменную и не вызывает ошибку, если её уже не было.

## Ошибка дня: путь модуля и путь файла

Импорт:

```python
from src.config import get_api_token
```

означает, что pytest ищет модуль по пути:

```text
src/config.py
```

Сначала файлы были созданы как `tests/api/config.py` и `tests/api/test_config.py`. Поэтому появился `ModuleNotFoundError: No module named 'src.config'`, а отдельная команда не нашла `tests/test_config.py`.

Исправление:

```text
src/config.py
tests/test_config.py
```

Это важный практический навык: при ошибке импорта нужно сопоставить dotted path (`src.config`) с реальным расположением файла (`src/config.py`).

## Почему тест не читает настоящий token

Автотест должен быть повторяемым и независимым от настроек компьютера. Поэтому он сам создаёт контролируемое значение через `monkeypatch`, а затем проверяет ожидаемый результат. Иначе тест мог бы пройти на одном компьютере и упасть на другом.

## Новые слова

- `environment variable` — настройка окружения процесса.
- `configuration` — параметры, меняющие поведение программы без изменения её логики.
- `secret` — конфиденциальный token, пароль или ключ.
- `monkeypatch.setenv` — временно установить переменную окружения в тесте.
- `monkeypatch.delenv` — временно удалить переменную окружения в тесте.
- `ModuleNotFoundError` — Python не смог найти импортируемый модуль.
