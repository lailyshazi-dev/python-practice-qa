# День 66: Page Object для конкретного элемента и фильтрации

## Цель урока

Научиться работать не с первым найденным элементом, а с конкретной записью внутри списка. Это важно, когда на странице несколько задач, товаров, пользователей или сообщений.

## Что сделано

- Добавлен метод `todo_item(title)`.
- Метод возвращает конкретную задачу из общего списка `todo_items`.
- `complete_todo(title)` теперь принимает название задачи.
- Checkbox ищется внутри выбранной задачи, а не на всей странице.
- Добавлен метод `show_completed()` для фильтра `Completed`.
- Добавлен тест с активной и завершённой задачами.
- Проверено, что после фильтра завершённая задача видна, а активная скрыта.

## Почему общий locator был недостаточен

Раньше Page Object содержал общий locator:

```python
self.todo_toggle = page.get_by_role(
    "checkbox",
    name="Toggle Todo",
)
```

При нескольких задачах такой locator может выбрать первый checkbox. Это не гарантирует, что будет изменена нужная запись.

Новый подход ограничивает поиск конкретной задачей:

```python
todo_item = self.todo_item(title)
todo_item.get_by_role(
    "checkbox",
    name="Toggle Todo",
).check()
```

Сначала выбирается контейнер задачи, затем checkbox внутри этого контейнера.

## `Locator.filter`

```python
def todo_item(self, title: str) -> Locator:
    return self.todo_items.filter(has_text=title)
```

`self.todo_items` представляет все элементы списка. `filter(has_text=title)` оставляет только тот элемент, внутри которого есть нужный текст.

Это пример scoped locator, то есть локатора с ограниченной областью поиска. Чем точнее область поиска, тем меньше риск взаимодействовать не с тем элементом.

## Фильтрация списка

```python
def show_completed(self) -> None:
    self.page.get_by_role(
        "link",
        name="Completed",
    ).click()
```

Тест проверяет не только действие, но и состояние списка:

```python
expect(
    todo_page.todo_item(completed_title)
).to_be_visible()
expect(
    todo_page.todo_item(active_title)
).to_be_hidden()
```

## Реальные примеры

### Интернет-магазин

В корзине может быть несколько товаров с одинаковой кнопкой удаления. Нельзя нажимать первый `Remove`. Сначала выбирают строку товара по названию, затем кнопку внутри строки:

```python
cart_page.product_row("Keyboard").get_by_role(
    "button",
    name="Remove",
).click()
```

### Таблица пользователей

В таблице у каждого пользователя есть кнопка редактирования. Page Object должен найти строку по email и нажать кнопку внутри неё, а не первую кнопку на странице.

### Чат

Для конкретного сообщения можно найти контейнер по тексту и проверить статус `Read` внутри этого контейнера.

## Что проверяет тест

Тест с двумя задачами демонстрирует сразу несколько важных свойств:

- задачи создаются независимо;
- завершается именно выбранная задача;
- фильтр меняет представление списка;
- активная задача не появляется в списке завершённых;
- assertions проверяют результат, а не детали реализации метода.

## Важная граница

Locator должен быть достаточно точным, но не чрезмерно хрупким. Предпочтение обычно отдают `role`, `label`, `placeholder` и `test id`. Если текст задачи уникален, `filter(has_text=title)` подходит. Если текст может повторяться, нужен более точный идентификатор записи.

В текущем классе старый общий `todo_toggle` больше не нужен и может быть удалён отдельной небольшой чисткой. Он не ломает тесты, но не должен оставаться неиспользуемым API Page Object.
