## Что понял

- Один тест может иметь несколько маркеров.
- Весь файл `tests/test_api_posts.py` помечен как `api`.
- Два негативных теста дополнительно помечены как `negative`.
- Команда `-m "api and negative"` запускает тесты, где есть оба маркера.
- Команда `-m "api and not negative"` запускает API-тесты, кроме негативных.
- В реальной работе маркируют не всегда каждый тест отдельно, а осмысленные группы тестов.

## Как делают в реальной работе

- Если весь файл относится к одной группе, удобно поставить маркер на весь файл через `pytestmark`.
- Если отдельный тест имеет особое значение, ему добавляют отдельный маркер.
- Smoke-тесты часто помечают вручную, потому что это самые важные быстрые проверки.
- Negative-тесты помечают, когда их нужно запускать отдельно.
- Slow/UI/API-тесты помечают, чтобы разделять тесты по скорости и типу.

## Код дня

```python
pytestmark = pytest.mark.api
```

```python
@pytest.mark.negative
def test_get_missing_post_returns_404(api_client):
    response = api_client.get_post(999999)

    assert response.status_code == 404
```

## Команды дня

```powershell
.\.venv\Scripts\python.exe -m pytest -m "api and negative" -q
.\.venv\Scripts\python.exe -m pytest -m "api and not negative" -q
.\.venv\Scripts\python.exe -m pytest -q
```

## Новые слова

- `and` - оба условия должны быть выполнены.
- `or` - достаточно одного условия.
- `not` - исключить тесты с маркером.
- `combined filter` - комбинированный фильтр.
- `test group` - группа тестов.

## Правило дня

Маркеры нужны не для украшения тестов, а для управления тем, какие проверки запускать в конкретной ситуации.
