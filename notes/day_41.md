# День 41: уникальные имена тестов

## Что я сделал

- Создал ветку `refactor/remove-duplicate-calculator-tests`.
- Нашел повторяющиеся имена тестов в `tests/test_calculator.py`.
- Удалил ранние дубли, которые Python перезаписывал более поздними функциями.
- Оставил версии тестов с маркерами `smoke`, `negative` и `regression`.
- Отформатировал длинный импорт из `src.calculator`, чтобы его было легче читать.

## Что понял

- В Python нельзя иметь две разные функции с одним и тем же именем в одном файле.
- Если функция объявлена повторно, новое определение заменяет старое.
- Для pytest это означает, что ранний тест с таким же именем может вообще не попасть в запуск.
- Поэтому каждый тест должен иметь уникальное имя.
- Маркеры лучше добавлять к существующему тесту, а не создавать второй тест с таким же именем.

## Где это нужно в реальной работе

- В команде один QA может случайно добавить тест с уже существующим именем, и старый тест перестанет запускаться.
- В большом проекте это опасно: кажется, что проверок много, но часть из них фактически не работает.
- При ревью автотестов уникальные имена помогают быстро понять, что именно проверяет каждый тест.
- В CI/CD важно, чтобы каждый тест был отдельной понятной проверкой, а не случайно перезаписанной функцией.
- Для портфолио чистые имена тестов показывают аккуратность и понимание того, как pytest собирает тесты.

## Пример проблемы

Плохо:

```python
def test_add_positive_numbers():
    assert add(2, 3) == 5


@pytest.mark.smoke
def test_add_positive_numbers():
    assert add(2, 3) == 5
```

В этом примере первая функция будет заменена второй.

Хорошо:

```python
@pytest.mark.smoke
def test_add_positive_numbers():
    assert add(2, 3) == 5
```

## Новые слова

- `duplicate` - дубль, повтор.
- `unique name` - уникальное имя.
- `test collection` - этап, когда pytest ищет и собирает тесты.
- `overwrite` - перезаписать.
- `dead test` - тест, который есть в файле, но фактически не запускается.

## Правило дня

Каждый тест должен иметь уникальное имя, иначе pytest может запускать не то, что ты ожидаешь.
