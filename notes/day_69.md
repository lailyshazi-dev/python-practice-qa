# День 69: артефакты диагностики Playwright

## Цель урока

Настроить автоматическое сохранение trace и screenshot при падении UI-теста, чтобы расследовать причину ошибки, а не воспроизводить её вслепую.

## Что изменено

В корневом `pytest.ini` настроено:

```ini
[pytest]
addopts = -q --tracing=retain-on-failure --screenshot=only-on-failure
```

Полный путь к файлу:

```text
C:\Users\Admin\Documents\qa_automation_course\python-practice-qa\pytest.ini
```

## Что делают параметры

### `--tracing=retain-on-failure`

Playwright записывает trace выполнения теста и сохраняет его, если тест упал. При успешном прохождении временный trace удаляется.

Trace помогает увидеть:

- последовательность действий;
- локаторы и их состояние;
- DOM на момент шага;
- сетевые запросы;
- время выполнения операций;
- точный шаг падения.

### `--screenshot=only-on-failure`

Screenshot создаётся автоматически только при ошибке. Это экономит место и оставляет артефакты, полезные для расследования.

## Почему не стоит сохранять всё всегда

Режим постоянной записи trace и screenshot увеличивает размер артефактов CI и время обработки результатов. Для обычного запуска достаточно сохранять их только при падении.

Полная запись может быть полезна при расследовании сложного flaky-теста, но это временная диагностическая настройка.

## Реальный пример

Если тест интернет-магазина падает после нажатия `Add to cart`, screenshot покажет состояние страницы, а trace позволит проверить:

- была ли кнопка видна;
- какой locator использовался;
- завершился ли запрос добавления;
- не появилось ли сообщение об ошибке;
- не произошёл ли переход на страницу авторизации.

Для формы оплаты trace может показать, на каком поле возникла ошибка валидации и какой сетевой запрос вернул неожиданный ответ.

## Как проверить доступность параметров

```powershell
.\.venv\Scripts\python.exe -m pytest --help |
    Select-String "tracing|screenshot"
```

В выводе должны быть:

```text
--tracing={on,off,retain-on-failure}
--screenshot={on,off,only-on-failure}
```

## Как исследовать падение

1. Найти упавший тест и его артефакты.
2. Посмотреть screenshot на момент ошибки.
3. Открыть trace через Trace Viewer.
4. Проверить locator, DOM, console и network.
5. Определить, ошибка в приложении, тесте или окружении.
6. Исправить причину и повторить targeted-запуск.

## Важное различие

Screenshot показывает один момент времени. Trace показывает историю выполнения и поэтому полезнее для таймингов, ожиданий и flaky-тестов.

Видео может дать дополнительный визуальный контекст, но обычно занимает больше места. Его включают осознанно, например только для падений в CI.

Автотест должен оставлять достаточно диагностической информации, чтобы причину падения можно было понять без повторного запуска вручную.
