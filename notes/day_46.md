# День 46: pytest.approx для проверки дробных чисел

## Что я сделал

- Создал ветку `feature/add-approx-float-tests`.
- Добавил параметризованный тест для деления с дробным результатом.
- Использовал `pytest.approx` для сравнения float-значений.
- Добавил понятные `ids` для параметров.
- Запустил новый тест отдельно в подробном режиме.
- Запустил все тесты проекта.
- Проверил файл через `git diff --check`.

## Что понял

- Дробные числа в Python не всегда удобно сравнивать через обычное `==`.
- Из-за особенностей хранения float результат может быть очень близким, но не идеально равным ожидаемому числу.
- `pytest.approx(expected)` позволяет сравнивать значения с небольшой допустимой погрешностью.
- Это полезно, когда важна не абсолютная точность до последнего знака, а корректное приближенное значение.
- `ids` помогают видеть понятные названия параметризованных сценариев в выводе pytest.

## Где это нужно в реальной работе

- Проверка процентов, скидок, рейтингов и коэффициентов.
- Проверка расчетов расстояний, координат, времени и скорости.
- Проверка API, который возвращает дробные значения.
- Проверка аналитики, статистики и средних значений.
- Проверка расчетов, где допустима маленькая погрешность.

Важно: для денег в реальных проектах чаще используют `Decimal`, а не обычный `float`.

## Код дня

```python
@pytest.mark.parametrize(
    "a, b, expected",
    [
        (1, 3, 0.3333333333),
        (2, 3, 0.6666666667),
    ],
    ids=["one-divided-by-three", "two-divided-by-three"],
)
def test_divide_returns_approx_float_result(a, b, expected):
    assert divide(a, b) == pytest.approx(expected)
```

## Как это читать

- `a` и `b` - числа, которые передаем в функцию `divide`.
- `expected` - ожидаемый примерный результат.
- `pytest.approx(expected)` - проверка приблизительного равенства.
- `ids` - понятные имена сценариев в выводе pytest.

## Новые слова

- `float` - дробное число с плавающей точкой.
- `approx` - приблизительно.
- `precision` - точность.
- `tolerance` - допустимая погрешность.
- `Decimal` - тип для более точной работы с числами, например с деньгами.

## Правило дня

Если тест сравнивает дробные значения, подумай, не нужен ли `pytest.approx` вместо обычного `==`.
