# День 40: понятные сообщения в assert

## Что я сделал

- Создал ветку `feature/add-api-assert-messages`.
- Добавил сообщения к `assert` в API-тестах.
- Сделал падения тестов более понятными для чтения.
- Оставил логику тестов прежней: мы не меняли, что проверяется, а только улучшили объяснение ошибок.

## Что понял

- Обычный `assert response.status_code == 200` проверяет условие, но при падении не всегда сразу понятно, что именно ожидалось.
- В pytest можно добавить сообщение после запятой:

```python
assert response.status_code == 200, "Expected status code 200"
```

- Сообщение показывается только если проверка упала.
- В сообщении полезно писать ожидаемый и фактический результат.
- Хорошее сообщение помогает быстрее понять причину падения теста.

## Где это нужно в реальной работе

- В CI/CD тест упал ночью после деплоя, и QA Automation Engineer быстро видит: ожидали `200`, получили `500`.
- Разработчик открывает отчет и сразу понимает, что сломался статус-код, структура ответа или тип поля.
- В большом проекте один тест может проверять много объектов в цикле, и сообщение показывает конкретный проблемный объект.
- Когда тесты смотрит другой человек из команды, понятные сообщения экономят время на разборе.
- В портфолио такие сообщения показывают, что тесты написаны не только "чтобы прошли", но и чтобы помогать расследовать баги.

## Примеры

Проверка статус-кода:

```python
assert response.status_code == 200, (
    f"Expected status code 200, got {response.status_code}"
)
```

Проверка поля в JSON:

```python
assert "title" in data, "Response should contain field 'title'"
```

Проверка значения:

```python
assert data["id"] == post_id, f"Expected post id {post_id}, got {data['id']}"
```

Проверка объекта в цикле:

```python
for post in data:
    assert "id" in post, f"Post should contain field 'id': {post}"
```


## Новые слова

- `assert message` - сообщение, которое pytest покажет при падении проверки.
- `expected` - ожидаемый результат.
- `actual` - фактический результат.
- `debugging` - поиск причины ошибки.
- `failure reason` - причина падения теста.

## Правило дня

Тест должен не только находить ошибку, но и помогать быстро понять, что именно сломалось.
