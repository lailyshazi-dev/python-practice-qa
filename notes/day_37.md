## Что я сделал

- Обновил раздел запуска тестов в `README.md`.

- Убрал лишнее дублирование команды `python -m pytest -q`.
- Упростил команды запуска API-тестов.
- Убрал лишние пробелы в командах.
- Запустил все тесты проекта.

## Что понял

- Если настройки pytest перенесены в `pytest.ini`, README должен это учитывать.
- `addopts = -q` уже включает короткий вывод по умолчанию.
- `testpaths = tests` уже указывает pytest, где искать тесты.
- Поэтому команды в README можно делать проще.
- Документация должна меняться вместе с кодом и настройками проекта.

## Где это нужно в реальной работе

- Новый QA открывает README и видит актуальные команды, а не устаревшие инструкции.
- Разработчик может быстро запустить нужный набор тестов перед коммитом.
- CI-команды проще переносить из README в pipeline.
- Если README не обновлять после изменения конфигурации, команда начинает запускать тесты разными способами.
- Хороший README снижает количество вопросов внутри команды.

## Команды дня

```powershell
python -m pytest
python -m pytest tests/api
python -m pytest -m api
python -m pytest -m "api and negative"
python -m pytest -m "api and not negative"
python -m pytest --html=reports/report.html --self-contained-html
```

## Новые слова

- `documentation drift` - ситуация, когда документация отстала от кода.
- `simplify` - упростить.
- `duplicate` - дублировать.
- `trailing space` - лишний пробел в конце строки.
- `configuration-aware documentation` - документация, учитывающая настройки проекта.

## Правило дня
